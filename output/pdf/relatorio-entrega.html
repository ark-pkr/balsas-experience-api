3. Descrição do projeto

A Balsas Experience API disponibiliza um catálogo de atrações turísticas de Balsas-MA. Permite consultar atrações, filtrar por categoria, tag e texto, acessar detalhes e registrar avaliações de visitantes. Também oferece operações para criar, atualizar e remover atrações.

Serve como fonte de dados para sites e aplicativos voltados a moradores e turistas. O projeto reúne informações dispersas em uma estrutura consultável e persistente: categorias organizam o catálogo, tags permitem cruzar interesses e avaliações registram a experiência dos visitantes.

5. Modelo de dados

PK = chave primária; FK = chave estrangeira. IDs inteiros são gerados automaticamente; campos sem indicação de opcional são obrigatórios.

TabelaCampos e restrições
Categoriaid: Int, PK; nome: String, único
Tagid: Int, PK; nome: String, único
Atracaoid: Int, PK; nome: String; descricao: String; cidade: String (padrão Balsas); estado: String (padrão MA); distanciaCentroKm: Int opcional; criadaEm: DateTime (agora); categoriaId: Int, FK → Categoria.id
Avaliacaoid: Int, PK; visitante: String; nota: Int; comentario: String opcional; criadaEm: DateTime (agora); atracaoId: Int, FK → Atracao.id
_AtracaoToTagA: Int, FK → Atracao.id; B: Int, FK → Tag.id. PK composta (A, B). Tabela de associação gerenciada pelo Prisma.

Relações: Categoria 1:N Atracao; Atracao 1:N Avaliacao; Atracao N:N Tag. Excluir uma atração remove suas avaliações e associações com tags em cascata; categorias e tags são preservadas. A API valida notas inteiras entre 1 e 5.

Por que separar tags? Uma tabela própria permite reutilizar a mesma tag em várias atrações, evitar duplicação de nomes e aplicar filtros por relacionamento.

6. Endpoints da API

MétodoCaminhoO que fazStatus
GET/Identificação do serviço200
GET/healthEstado do processo HTTP200
GET/atracoesListagem por nome; categoria e tags incluídas200
GET/atracoes?categoria=Lazer
&tag=lazer&q=rio		Filtros combinados, sem diferenciar maiúsculas200
GET/atracoes/:idDetalhes, avaliações, média e total200 / 404
GET/categoriasCategorias e contagem de atrações200
POST/atracoesCriar atração201 / 400 / 409
PUT/atracoes/:idSubstituir dados e tags200 / 400 / 404 / 409
DELETE/atracoes/:idExcluir atração e avaliações204 / 404
POST/atracoes/:id/avaliacoesCriar avaliação de visitante201 / 400 / 404

Falhas inesperadas podem retornar 500. /health não verifica o banco. POST e PUT exigem nome, descricao e categoria. Cidade, estado, distância e tags são opcionais. PUT substitui tags e restaura os padrões dos campos opcionais omitidos.

7. Como executar o projeto

Pré-requisitos: Node.js 24 LTS, npm, Git e acesso a um PostgreSQL local ou hospedado. Execute os comandos na raiz do repositório.

1. Clonar e instalar

git clone https://github.com/ark-pkr/balsas-experience-api.git
cd balsas-experience-api
npm ci

O repositório público está indicado na seção 9.

2. Configurar o ambiente

Copie .env.example para .env e substitua os exemplos pelas credenciais do seu banco. Não publique o .env.

DATABASE_URL="postgresql://USUARIO:SENHA_FICTICIA@HOST-POOLER/neondb?sslmode=require"
DIRECT_URL="postgresql://USUARIO:SENHA_FICTICIA@HOST-DIRETO/neondb?sslmode=require&connect_timeout=30"
PORT=3000

A aplicação usa DATABASE_URL. O Prisma CLI usa DIRECT_URL ou, se ausente, DATABASE_URL. As senhas acima são fictícias.

3. Gerar cliente, migrar e popular

npx prisma generate --config prisma7.config.ts
npx prisma migrate deploy --config prisma7.config.ts
npm run seed

Atenção ao seed: apaga os dados existentes antes de inserir oito atrações e três avaliações. Use apenas em banco novo ou descartável; pule essa etapa se o banco já estiver populado.

4. Iniciar e verificar

npm start
# Em desenvolvimento, alternativamente: npm run dev
# Em outro terminal:
curl -i http://localhost:3000/health
curl -i http://localhost:3000/atracoes
npm test

No PowerShell, use curl.exe. Os testes usam a porta 3108 e criam/removem uma atração temporária. Os 15 cenários passaram na verificação local.

Publicação preparada

O arquivo render.yaml configura um Web Service no Render com Node.js 24.13.1. Build: npm ci --include=dev && npm run build; início: npm start. Cadastrar DATABASE_URL e DIRECT_URL no painel. O build aplica migrações e não executa seed. A hospedagem fornece PORT.

Conceitos técnicos demonstrados pelo projeto

Prisma 7: o cliente usa o adaptador PrismaPg para acessar PostgreSQL. Modelagem: tags reutilizáveis são associadas às atrações em uma relação N:N. Integridade: a exclusão em cascata evita avaliações sem atração. HTTP: criação retorna 201 e Location; remoção retorna 204 sem corpo; registro ausente retorna 404.

Esses conceitos são verificáveis no código; a experiência pessoal de cada integrante será inserida após a confirmação em docs/RELATOS-EQUIPE.md.
